## 0. Goal and invariants

**Goal.** Every page that shows history reads settled days and closes instead of replaying the
ledger once per day, so prod's dashboard drops from 16–64 s to well under a second. Every money
figure stays exactly the number it is today, and the owner can always see what the settlement
did, is doing and will do (PERF-D10, the run reports).

**Invariants (breaking one is a bug, not a choice):**

1. **Byte identity against v0.1.31.** With the store clean, or dirty only inside the live window,
   `/api/dashboard` is byte-identical to what **v0.1.31's code** produces for the same database and
   clock. This is checked on every corpus against reference payloads generated by that code (W0.2),
   never against the new code with the store switched off. The golden payload never changes. The only
   intended differences are:
   - the labelled stale range (spec §10);
   - the additive optional `/api/snapshots` fields (spec §11.4);
   - a dependency teardown failure now answering 500 instead of a silent 200 (P1, recorded in
     CHANGELOG).
2. **Money.** No money-of-record formula, rounding or ordering changes (spec §3 non-goals). Decimal
   is used end to end and stored as canonical TEXT (`money.to_db`). The tax package is byte-identical
   to v0.1.31's on every corpus. The frontend only formats server strings.
3. **The ledgers stay the only source of truth.** The store is derived. Dropping it (triggers first)
   loses nothing, and a run rebuilds it.
4. **A GET never writes** (DEF-065). The store is written only by the run, at boot, or by a mutating
   request. Triggers are created at boot only, and the actor TEMP trigger never exists on a GET or
   read-only-POST connection.
5. **Layering** (`architecture.md`):
   - calculation stays in `portfolio/`;
   - orchestration lives in `api/`;
   - `scheduler/` reaches the settlement only through registered seams;
   - `cost_basis.py` and `results.py` stay leaves;
   - the worker never imports `fastapi`, `litellm`, `yfinance`, `pandas`, or any `api`,
     `scheduler`, `export`, `strategy`, `news`, `ops` or `llm_insight` module.
6. **Refusals are unchanged.** 待釐清 and refused rows mark the same days incomplete and withhold the
   same figures.
7. **Project rules:**
   - a state colour is a class, and there are no native dialogs;
   - every mutating route has an action-log label;
   - every `job_runs.detail` is a zh sentence (DEF-073), and every rule id has a zh name (DEF-062);
   - every new route has a frontend caller or an allowlist entry;
   - `PD_SETTLE=off` restores today's behaviour, running on the new engine.

**Process:**
- Write the failing test first for every behaviour.
- While fixing, run only ruff and targeted tests.
- **Heavy gates once, after the final review, one at a time:**
  1. ruff;
  2. mypy --strict (fresh `--cache-dir`);
  3. pytest non-e2e (batch totals = `--collect-only`);
  4. e2e in ≤ 11-test foreground chunks;
  5. stress phase 1.
- **One exception, mandated by the spec:** stress phase 1 also runs at the wave-1 merge, as WP2's
  gate.
- Use `C:\AI-Workspace\invest-portfolio\.venv\Scripts\python.exe` from the worktree root.
- Worktree subagents come up on `main`. Each first runs `git reset --hard <wave base sha>` and reports
  its merge-base.
- **Children spawned from a worktree must run that worktree's code.** The editable install maps
  `portfolio_dash` to the main checkout, so `child_runner` sets `cwd` and `PYTHONPATH` to the
  package's own root and never uses `-I` (W0.7).
- **Subagents never touch:** `CHANGELOG.md`, `api/app.py`, `tests/conftest.py`,
  `tests/e2e/conftest.py`, `.claude/rules/*`, the accounting manuals, `shared/whatsnew.py`.
- Commit with a scoped `git add` and the session's commit trailer.
- Merge by cherry-pick, and re-run the seam tests after each pick.
- **No real data** in any test, fixture, doc or commit (the repo is public). The two real-data
  scratch DBs are opened only by `scripts/perf/*` on the dev machine, via `--db`.

- [ ] **W0.7 Flags, locks, runner** (P5, P6):
  - **`proc_lock`:**
    - Linux uses `fcntl.flock` (never `lockf`: closing any fd drops a `lockf` lock process-wide).
    - Windows uses `msvcrt.locking` on byte 0 after `lseek(0)`. `LK_NBLCK` is the probe; `LK_LOCK`
      is not blocking (it gives up after ~9 s, errno 36), so `lock()` is a retry loop. The lock is
      mandatory (other processes cannot read the locked byte), so a lock file holds no data.
    - API: `try_lock(path) -> Handle | None`, `lock(path, timeout)`, `is_held(path) -> bool`
      (non-blocking probe; PermissionError / EACCES / EAGAIN mean held).
  - **Lock files:**
    - `<data>/settlement.lock`: held by the settle child for its whole life;
    - `<data>/heavy-child.lock`: held by the runner's gate while a heavy child lives;
    - `<data>/job-<run_id>.lock`: held by a job child, so boot can finalise an orphan job run whose
      lock is free.
