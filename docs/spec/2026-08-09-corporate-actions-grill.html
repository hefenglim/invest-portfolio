Q1 多帳戶只補一半:宣稱的安全網不會觸發

規格 §5.1 detail 3 寫著：一檔股票在 N 個帳戶都有部位、公司行動列卻只補了其中 M 個時，「抽屜會對那個帳戶顯示 ⚠ 對帳不一致」。照現在的程式碼與 §6.3 的新恆等式推，這句話不成立。沒補列的帳戶，corporate_delta 正好是 0，build_book 也一樣什麼都沒套用，恆等式兩邊完全相等，頁尾印出來的是綠色的 ✓ 對帳一致。可是 prices 這張表沒有 account_id，價格修正是全市場一次到位 —— 那個帳戶於是拿分割前的股數去乘分割後的價格，市值整整少掉一個分割倍數，而全站沒有任何一段程式在看這件事。

Q3 同日行動的順序會改變金額,而守恆測試看不見

規格 E12 把同一天的兩筆行動交給 id ASC 排序，並稱之為「有文件記載的確定性 tie-break」； 但 id 是 INTEGER PRIMARY KEY AUTOINCREMENT，它記錄的是這兩列被打字進系統的先後， 不是這兩件事在市場上發生的先後。實測同一份帳、同一天、同樣兩列（X 100 股、成本 5,000；一筆 3 併 1 分割、一筆 X→Y 2 換 1）， 只把輸入先後對調，Y 的最終股數就從 600 變成 200（差 3 倍），每股均價從 8.33 變成 25.00； 而真正要緊的是第二件事——§2.1 的守恆律、以及規格自稱「最便宜的偵測器」的 §7.1a 屬性測試， 在兩種順序下都是綠的（Σ original_total 兩邊都是 5,000）， 所以這個把股數與均價一起挪動 3 倍的缺陷，在 CI 裡不會亮任何一盞紅燈。

現況／規格如寫

E12：同日同標的的兩列，以 id ASC 決定套用順序。因為 id 是自動遞增流水號， 這條規則實際上把金額的答案綁在「擁有者當天先打哪一列」上——這是輸入習慣，不是市場事實， 而且事後從報表上完全看不出來。更糟的是唯一會看這件事的安全網（§7.1a）對它免疫： EXCHANGE 整包搬走成本，兩種順序的 Σ original_total 都不變， 守恆律只約束成本總額，從來沒有約束股數。

Q7 改名前的識別碼該不該成為一等 symbol

券商匯出檔在一檔證券的識別碼改變時（合併、強制反分割、識別碼重編），會把舊部位用那串原始識別碼字串寫出來、新部位用 ticker 寫進去 —— 而 ticker 本身往往沒有變，變的只有識別碼。匯入器若照單全收，那串識別碼就成了帳本裡的一個 symbol：依 E10 它必須先被註冊進 instruments（得填市場、計價幣別、類股），又因為 from_symbol 與 to_symbol 不相等，依 E20 這筆行動只能記成 EXCHANGE。整份規格從頭到尾沒有問過那個真正的問題：那串識別碼到底算不算一檔證券？它是本次規格裡少數幾個「一句裁決決定三個地方」的根問題 —— 答案同時決定 Q6 的範圍擴張是「建議」還是「必要」，也決定匯入介面要不要多一道確認步驟。

分支 A

把識別碼當成一等 symbol 註冊進 instruments。代價是四件事同時發生：它需要一組它其實沒有的市場／計價幣別／類股；它永遠不會在任何 provider 上解析成功，於是每一輪報價更新都把它丟回 failed，變成一個永久失敗的鍵；行動記完之後它是 0 股，直接從 holdings 消失，於是它在唯一能解釋它的地方看不到、只在看起來像故障的地方看得到；而且因為兩個 symbol 不相等，E20 只允許 EXCHANGE，Q6 那個「目的地 ticker 的舊價仍停在舊股數口徑」的問題就被整包拖進來。連帶地，符號選擇器、類股配置、instrument 清單都會多出一列不是證券的東西。

分支 B（建議）

在匯入時就把識別碼正規化成它的 ticker。理由很簡單：那串識別碼和那個 ticker 是同一檔證券的兩個身分，不是兩檔證券。解析來源是同一個券商事件群組裡兄弟列上的 ticker；解析不出來就停下來問擁有者，絕不猜。正規化之後 to_symbol == from_symbol，E20 自動把它判成 SPLIT，而 §5.1(d) 本來就處理 SPLIT 的價格歷史 —— Q6 的問題不是被解決，是根本沒有發生，而且沒有新增任何機制。instruments 維持是一張證券表。成本是匯入器多一道需要擁有者確認的解析步驟。界線要講明：這條規則只管「識別碼變了、ticker 沒變」；真正併進另一檔 ticker 的合併，兩個 symbol 本來就不同，依 E20 仍然是 EXCHANGE，不受影響。

Q8 現金加換股的併購沒有模型,也沒列入不做

「A 的每一股換 0.6 股 B，另外配發現金 US$12.00」——現金加換股是市場上最常見的併購形式之一。 規格 §4 只模型化三種行動（SPLIT／EXCHANGE／SPINOFF），§9 也明列了四件明確不做的事， 而這個事件兩邊都不在：既沒有算法，也沒有禁令。§10 開宗明義說這份文件 「要交給實作代理人當作 brief」，那麼代理人碰到它時只會做一件事——用手上僅有的詞彙硬記成一筆 EXCHANGE。 實測：A 100 股、成本 5,000.00 換成 B 60 股，B 背著全部 5,000.00 的成本，均價 83.33； 而真正收到的 1,200.00 現金哪一本帳都沒有進——不是收入、不是已實現損益、也不是 XIRR 的現金流。 §2.1 的守恆律照樣 PASS，因為 Σ original_total 一毛沒少：這筆錢是離開帳本， 不是在帳本裡被搬錯位置，而守恆律從來只約束帳本裡面的東西。

規格如寫

現有詞彙只給得出一種寫法：一列 EXCHANGE。§4.2 把來源部位的成本 100% 搬到目的地並把來源清成 0， 整條公式裡沒有任何欄位承接現金腿。後果是三件事一起發生：現金 1,200.00 無處落腳、 B 的每股成本被高估到 83.33（它背著已經被現金換走的那一段成本）、淨值悄悄短少 1,200.00。 最危險的是安全網會是綠的——§10.1(2) 把守恆訂為驗收測試，但它加總的是成本總額， 而這筆錢是離開帳本，不是在帳本內位移。

建議

按對價比例分攤成本——這正是 §3.2 對「零股找現」已經在用的原則。股票對價 60 × 30.00 ＝ 1,800.00、 現金對價 1,200.00，合計 3,000.00 → 現金腿佔 40.00%；分攤到現金腿的成本 5,000.00 × 40.00% ＝ 2,000.00，已實現損益 1,200.00 − 2,000.00 ＝ −800.00； 其餘 3,000.00 結轉給 B，B 均價 50.00。落地形式不是第四種行動， 而是兩列既有的東西：一筆普通 SELL（現金腿）＋ 一筆 EXCHANGE（其餘）。

Q9 分拆出的子公司會繼承母公司的回本進度

這一題的算術是正確的，守恆律也成立 —— 問題完全在畫面上那句話說了什麼。規格 §4.3 讓分拆把母公司的 original_total 與 adjusted_total 同時乘上分配比例 c，這是對的：Σ 三個總額分拆前後不變（§2.1 表列 −c·P + c·P = 0）。但 payback_ratio 的分子與分母被同一個 c 乘過，c 就約掉了，於是子公司的比率恆等於母公司的比率。一家去年才分拆出來、成立以來從未發過一毛股利的公司，抽屜上會寫著「回本進度 40.00%・配息 / 原始成本」—— 那 40% 是別人、在它存在之前發的股利。在加權平均法之下這個數字有它的道理（成本承接過來了，回收也隨著成本承接過來），所以這不是計算缺陷；但標籤講的是一件沒發生過的事，而本專案的整個立場就是攔下「長得很對的數字」。要不要改、怎麼改，是誠實標示的取捨，只有 owner 能裁決。
