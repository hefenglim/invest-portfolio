## 1. DEF-077（複驗未過・低）——「一致」與「無法比較」仍是琥珀色警示框

**已通過的部分**
- demo 的三組匯率日期不同：USD/MYR 09-24、MYR/TWD 09-22、USD/TWD 09-25。
- `GET /api/dashboard` 的 `freshness.fx_triangulation` 回傳 `ok: true`、`compared_on: 2026-09-22`、`dates_differ: true`，`leg_dates` 正確。
- 首頁「資料新鮮度」提示文字：「匯率三角一致性 USD/TWD：USD/MYR × MYR/TWD 推得 31.663000，直接報價 31.663000，落差 0.0000%（一致）・日期不同（各組最新：USD/MYR 2026-09-24、MYR/TWD 2026-09-22、USD/TWD 2026-09-25），以共同日期 2026-09-22 比較」✓
- J-01 重跑時，三角檢查為 `ok: true`。

**沒通過的部分（demo 真實瀏覽器，getComputedStyle）**
- 這則「（一致）」提示的計算樣式是 `color: rgb(217, 161, 63)`、`background: rgba(217, 161, 63, 0.14)`。這和同一區的「排程器未啟動」警示是**同一個琥珀色警示框**。
- 使用者看到的是一則寫著「一致」、卻用警示色標示的提示。

**根因**
- `web/styles.css:1240-1247` 的 `.fresh-note` 預設 `color: var(--amber)`、`background: var(--amber-soft)`。
- `web/app.js:1393-1420` 只在 `t.ok === false` 時設定 inline 琥珀色，`true`／`null` 沒有換成中性樣式。所以三種狀態看起來都是琥珀色。
- 這和 `app.js:1395` 的註解、以及 R6 來回記錄 H 欄寫的設計（「只有 ok === false 顯示琥珀色；ok === null 中性」）不一致。

**為什麼測試沒攔到**
- `tests/e2e/test_def077_fx_triangle_note_flow.py:65` 讀的是 `n.style.color`（只有 inline），`:93` 斷言它等於 `""`。
- CSS 預設的琥珀色不會出現在 inline，所以測試照樣通過。
- 這和 R5 DEF-056 的 `to_have_text` 盲點同類：只驗「我設了什麼」，沒驗「使用者實際看到什麼」。

**規格**
1. `ok === true` 與 `ok === null` 的匯率三角提示改用中性樣式，也就是一般文字色、無琥珀底。做法不限，例如另設 class 覆寫 `.fresh-note` 的顏色與底色，或把三角提示移出 `.fresh-note`。
2. 只有 `ok === false` 維持琥珀色警示框。
3. 「日期不同…以共同日期 X 比較」的文字維持現狀。

**測試**
- e2e 改用 `getComputedStyle` 驗 `color` 與 `background-color`：一致與無法比較都不是琥珀色；`ok: false` 是琥珀色。
- 變異：把中性 class 拿掉，測試必須失敗。

**同類掃描**：列出所有「容器 class 已有預設警示色，但程式用 inline style 判斷顏色」的提示，並附數字。

**驗收**：驗證者在 demo 首頁鮮度面板讀計算樣式，並以本機環境製造 `ok: false` 與「無共同日期」兩種情況比對顏色。
